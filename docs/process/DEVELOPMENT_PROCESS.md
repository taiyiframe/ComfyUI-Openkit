# Openkit 工程化开发流程 SOP（企业级测试体系落地）

> 宪法 §四 的展开。源自企业级测试体系（测试金字塔、静态门禁、行为优先、分层验证、回归与留痕）。
> 每任务必执行：方案确立后先列 checklist → 逐项工程化 → 验证通过勾选展示 → 自动下一项 → 留痕留档 → 交付文档。

## 六段流水线（每段有质量门禁 Gate，不过不进下一段）

```
① 方案与基线 ──Gate──▶ ② 静态检查 ──Gate──▶ ③ 单元测试 ──Gate──▶ ④ 实现 ──Gate──▶ ⑤ 集成验证 ──Gate──▶ ⑥ E2E + 交付
```

### ① 方案与基线
- 读全需求与输入 → 探查现状（定位代码/行号/事实）→ 输出方案要点 → 列出全局 checklist（写入留痕文档）。

### ② 静态检查（快反馈门禁）
- JS：`node --check <file>`（全部 web/js/*.js）
- Python：`<venv>\Scripts\python.exe -m py_compile`（全部 nodes/*.py + __init__.py）
- 额外扫描：残留硬编码中文 / 未翻译文案、TODO/FIXME、明显死代码。

### ③ 单元测试（纯逻辑，70%）
- 用 node:test（Node ≥18），mock 浏览器全局（localStorage/navigator/window/CustomEvent）与 `scripts/app.js`。
- 覆盖：i18n 双向翻译、占位符、正则规则、持久化、数据契约不误翻；编号/校验等纯函数。
- 原则：测试行为而非实现；快而多。

### ④ 实现
- 按 checklist 逐项修改；**禁止批量替换**，保证语法语义逻辑正确；改一处验证一处。

### ⑤ 集成验证（行为，20%）
- 语言切换全量生效（全部节点 + 后端显示名）、刷新持久化、无残留未翻译硬编码、用户数据不误翻。
- 模块交互：MediaLoader ↔ ReferenceSplitter 联动、Tab 索引切换等回归。

### ⑥ E2E / 交付（少而精，10%）
- ComfyUI 运行时加载、测试工作流渲染无报错。
- 清理中间产物 → 归档中间版本 → 中英双语 README/使用文档 → git 提交（双平台同步）→ 归档对话日志。

## 留痕要求
- 每任务一个留痕文档（`99_日志/DEVELOPMENT_LOG_<任务>.md`），记录：背景、病灶证据、方案、checklist 及逐项结果证据。
- git 每个完成点一个 commit，打 tag 标注中间重要版本（`03_归档版本`）。
- 交付说明列出：验证方式、覆盖范围、结果、仍存在的缺口。
